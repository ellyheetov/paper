4. AI 품질 및 안정성

2026년 11월 4일 · 약 3분

Evaluation​

AI가 만든 결과가 기대한 수준인지 측정하는 것

AI는 같은 입력에도 매번 다른 결과를 낼 수 있어서, 한 번 잘 됐다고 품질이 보장되지 않아요. 그래서 기준과 테스트 데이터를 정해두고 결과를 반복해서 측정해요.

방식의미예시
규칙 기반정답이나 규칙과 직접 비교테스트 통과 여부, JSON 형식 검사
사람 평가사람이 결과를 직접 보고 판단코드 리뷰, 답변 만족도
LLM-as-a-Judge다른 AI가 기준에 따라 채점"질문에 맞는 답인가?" 1~5점

프롬프트나 모델을 바꿨을 때 정말 나아졌는지도 같은 기준으로 비교할 수 있어요.

Guardrails​

AI가 해도 되는 일과 하면 안 되는 일의 경계를 정하는 것

AI가 위험한 작업을 실행하거나 잘못된 정보를 내보내지 않도록, 입력·출력·행동에 제한을 두는 장치예요.

위치하는 일예시
입력들어오는 요청을 검사개인정보, 프롬프트 인젝션 차단
출력내보내는 결과를 검사민감 정보 마스킹, 형식 검증
행동실행할 수 있는 작업을 제한파일 삭제·배포 전 사람 승인

두 개념 비교하기​

개념핵심 질문시점
Evaluation결과가 잘 나왔나?결과가 나온 뒤 측정
Guardrails해도 되는 일인가?실행 전·실행 중 차단

Evaluation은 품질을 높이고, Guardrails는 사고를 막아요. Loop Engineering에서는 Evaluation 결과가 다시 수정할지 판단하는 기준이 돼요.
