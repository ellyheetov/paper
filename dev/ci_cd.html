1. CI/CD란?​

CI/CD는 개발자가 작성한 코드를 자동으로 검증하고, 앱을 배포하는 과정을 자동화하는 방법이에요.

  • CI (Continuous Integration): 코드를 통합할 때 자동으로 빌드하고 테스트해요.
  • CD (Continuous Delivery / Deployment): 검증된 결과물을 배포할 수 있도록 준비하거나 실제로 배포해요.

예를 들어 개발자가 GitHub에 Pull Request를 올리면 CI가 자동으로 빌드와 테스트를 실행하고, main 브랜치에 병합되면 배포하는 식이에요.

2. Runner란?​

Runner는 GitHub Actions에서 Job을 실제로 실행하는 컴퓨터예요. iOS 앱을 빌드하려면 macOS와 Xcode가 필요하기 때문에 macOS Runner를 사용해요. Runner는 크게 두 종류가 있어요.

구분GitHub-hosted RunnerSelf-hosted Runner
장비GitHub가 관리하는 가상 머신직접 준비한 Mac (Mac mini 같은 물리 장비)
관리별도 Mac 서버를 관리할 필요가 없음Xcode 버전이나 실행 환경을 직접 관리
지정 방법runs-on: macos-latestruns-on: [self-hosted, macOS]

3. Multi Runner​

Mac mini 한 대에 Runner를 여러 개 설치해도 장비 자체는 하나이기 때문에 일부 자원을 공유해요.

  • 공유 자원: CPU, RAM, Disk, Xcode, Keychain

따라서 다음 항목을 관리해야 해요.

항목주의할 점권장 방법
Working Directory작업 파일 충돌Runner별 분리
DerivedData빌드 결과물 충돌-derivedDataPath로 분리
Simulator기기 상태 및 테스트 간섭Runner별 Simulator UDID 분리
Xcode버전 변경으로 인한 간섭DEVELOPER_DIR 지정
Keychain인증서 및 서명 작업 간섭별도 관리 또는 직렬화(한 번에 하나씩 실행)
CPU / RAM동시 빌드로 인한 성능 저하동시 실행 수 제한
